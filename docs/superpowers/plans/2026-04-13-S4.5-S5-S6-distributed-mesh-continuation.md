## Where we stand at the start of S4.5

Architecture after S4:
- **all-in-one mode** (default): one process owns everything. `--two-hosts` from S3 distributes cells across in-process `Host` instances with real gRPC loopback between them. Fully playable.
- **coordinator mode** (`--mode=coordinator`): MeshControl gRPC server on `:9100`, admin console, no local cells. Maintains `HostRegistry` of registered nodes, runs rendezvous assignment, handles heartbeats + crash reassignment.
- **node mode** (`--mode=node --coordinator-addr=host:9100`): registers with coordinator, dials with exponential-backoff reconnect, creates cells dynamically on `CellAssign`, sends `CellReady`/`CellStopped`, sends `Heartbeat` every 1s. Re-announces owned cells on reconnect for coordinator-restart recovery.

The gap S4 left open (acknowledged in the S4 plan's "Out of scope" section):
- Node mode's `assignCellOnNode` installs a plain `cellBridge`, NOT a `grpcBridge`. So when cell_0_0 (on node A) tries to push a border frame to cell_1_0 (on node B), the `cellBridge` looks up `coord.Cells[cell_1_0]` in its own process — which is empty because the cell lives on node B. The frame silently disappears.
- Nodes don't know each other exist. There's no `PeerList` distribution, so a node's `HostNetwork.peers` map is empty, so `SendLossy`/`SendReliable` would return `"no peer"` even if `grpcBridge` was wired.
- The `cellToHostMap` only exists on the coordinator. Nodes don't have a copy, so `grpcBridge.resolveDest` has no way to answer "which host owns this cell?".

Phase S4.5 closes exactly these three gaps. Nothing more.

# Phase S4.5: Cross-node MeshData routing

**Goal:** A cell on node A can send a border frame or handoff message to a cell on node B, and it actually arrives over the gRPC MeshData stream. Validated via an integration test that starts two in-process node instances connected to one coordinator and verifies cross-node traffic end-to-end.

**Architecture:**
- Coordinator broadcasts `PeerList` to every node whenever the host roster changes (registration, crash reassignment, graceful leave). `PeerList` already exists as a proto message (S3 Task 2 defined the whole MeshControl schema). We just never sent it.
- Node receives `PeerList`, walks the list, calls `HostNetwork.ConnectPeer` for each new peer, ignores peers it's already connected to, and closes connections for peers that dropped off the list.
- Coordinator also broadcasts a fresh `PeerList` alongside the first `CellAssign` in every rebalance — ensures a newly-registered host has its peer map populated before it receives cell assignments that might route cross-host.
- Node's `cellToHostMap` is populated from `CellAssign` and `CellRelease` messages. Each time a cell is assigned, the node records `cellID → hostID` for every cell mentioned in the assignment (both self-cells and peer-cells — the coordinator tells the node about every cell in the cluster, not just the ones it owns, so `grpcBridge.resolveDest` works for outbound routing).
- Actually simpler: the `PeerList` message carries a full `CellOwnership` table (a new sub-message) that every node receives. Nodes rebuild their `cellToHostMap` from it on every `PeerList` update. Single source of truth flows from coordinator → nodes, no incremental reconciliation.
- Node-mode `assignCellOnNode` wraps the newly-created cell's `Bridge` in a `grpcBridge` (same pattern as S3 Task 7's multi-host wiring). `resolveDest` looks up the destination in the locally-cached `cellToHostMap`; same-host destinations take the local shortcut, cross-host destinations go through the grpc path via `HostNetwork.SendLossy`/`SendReliable`.

**Research-driven design choices (from the master-plan research pass):**
- **Cell ownership table in PeerList, not incremental delta** — simpler reconciliation, small payload (<1KB for 100 cells), and rendezvous rebalance touches most cells anyway so delta wouldn't save much.
- **`grpcBridge.cellToHost` is a closure reading from a mutex-guarded map** — same pattern as S3. Thread-safe reads during cell dispatch, safe mutations from the control-plane goroutine.
- **No reverse registration** — nodes don't gossip directly. All peer discovery flows through the coordinator. Simpler trust model, no split-brain, fewer moving parts.
- **PeerList broadcasts are idempotent** — nodes receiving a PeerList they already have just no-op. No version numbers or delta counters.

**Proto changes needed:** one small addition to `CoordMessage_PeerList` — extend `PeerList` to carry a repeated list of cell ownership tuples. The message already exists; we augment it.

**Tech stack:** No new dependencies. All work inside `pkg/universe/`.

```go
// buildPeerList constructs a CoordMessage_PeerList from the current
// HostRegistry snapshot. Called by broadcastPeerList after rebalances.
func (e *assignmentEngine) buildPeerList() *meshpb.CoordMessage {
    live := e.registry.LiveHosts()
    hostRecs := make([]*meshpb.HostRecord, 0, len(live))
    for _, h := range live {
        if h.State != RemoteHostLive && h.State != RemoteHostRegistered {
            continue
        }
        hostRecs = append(hostRecs, &meshpb.HostRecord{
            HostId:   h.ID,
            GrpcAddr: h.GrpcAddr,
        })
    }
    ownership := make([]*meshpb.CellOwnership, 0)
    for _, h := range live {
        for cellID := range h.OwnedCells {
            ownership = append(ownership, &meshpb.CellOwnership{
                CellId: cellID,
                HostId: h.ID,
            })
        }
    }
    return &meshpb.CoordMessage{
        CoordEpoch: e.coord.coordEpoch,
        Msg: &meshpb.CoordMessage_PeerList{
            PeerList: &meshpb.PeerList{
                Hosts: hostRecs,
                Cells: ownership,
            },
        },
    }
}
```

```go
// broadcastPeerList sends the current PeerList to every registered
// host. Called after onHostRegistered (post-settle), after every

func (e *assignmentEngine) broadcastPeerList() {
```

```go
// DisconnectPeer closes the outbound stream to the given peer. Used
// for graceful peer removal when the coordinator's PeerList drops a
// host (after crash reassignment, graceful leave, etc.). Safe to
// call on an unknown peer — it's a no-op.
func (n *HostNetwork) DisconnectPeer(hostID string) {
    n.mu.Lock()
    peer, ok := n.peers[hostID]
    if ok {
        delete(n.peers, hostID)
    }
    n.mu.Unlock()
    if !ok {
        return
    }
    peer.cancel()
    _ = peer.conn.Close()
}
```

This parallels `dropPeer(self *hostPeer)` but is driven by control-plane events rather than Send errors.

- [ ] **Step 2: `applyPeerList` on meshControlClient**

Add to `mesh_control_client.go`:

```go
// applyPeerList updates the node's local view of peer hosts and cell
// ownership from a coordinator broadcast. Safe to call from the recv
// loop goroutine.
//
// Peer reconciliation: connect to any host in the list we don't
// already have a stream to; disconnect from any peer we have that's
// not in the list. Skip our own host ID (we never connect to ourselves
// — same policy as coordinator's cross-connect loop in Task 7 of S3).
//
// Cell ownership: atomically replace the coordinator's cellToHostMap
// so the node's grpcBridge.resolveDest can look up destinations.
func (c *meshControlClient) applyPeerList(pl *meshpb.PeerList) {
    if pl == nil {
        return
    }

    host := c.coord.localHost()
    if host == nil || host.Network == nil {
        return
    }

    // Reconcile peer connections.
    wanted := make(map[string]string, len(pl.Hosts))
    for _, hr := range pl.Hosts {
        if hr.HostId == c.hostID {
            continue // skip self
        }
        wanted[hr.HostId] = hr.GrpcAddr
    }

    // Connect to new peers. Idempotent — ConnectPeer replaces any
    // existing stream for the same host ID.
    for hid, addr := range wanted {
        if err := host.Network.ConnectPeer(hid, addr); err != nil {
            c.log.Log(CatMeshCell, "node: ConnectPeer %s (%s) failed: %v", hid, addr, err)
        } else {
            c.log.Log(CatMeshCell, "node: connected to peer %s (%s)", hid, addr)
        }
    }

    // Disconnect peers not in the wanted set.
    host.Network.mu.RLock()
    existing := make([]string, 0, len(host.Network.peers))
    for hid := range host.Network.peers {
        existing = append(existing, hid)
    }
    host.Network.mu.RUnlock()
    for _, hid := range existing {
        if _, keep := wanted[hid]; !keep {
            host.Network.DisconnectPeer(hid)
            c.log.Log(CatMeshCell, "node: disconnected from peer %s", hid)
        }
    }

    // Atomically replace cellToHostMap.
    newMap := make(map[string]string, len(pl.Cells))
    for _, co := range pl.Cells {
        newMap[co.CellId] = co.HostId
    }
    c.coord.mu.Lock()
    c.coord.cellToHostMap = newMap
    c.coord.mu.Unlock()
    c.log.Log(CatMeshCell, "node: applied PeerList (%d peers, %d cells)", len(wanted), len(newMap))
}
```

# Phase S5: Postgres persistence

**Goal:** Replace BoltDB with PostgreSQL via pgx/v5. Player state lives in a `players` table with a JSONB data column for game-specific fields. Schema migrations run via `go:embed`'d SQL files. Per-cell async writer batches upserts through `pgx.Batch`. Docker compose for local dev. Integration test against a real Postgres instance.

**Why now:** Parallel-able with S6 per the spec's dependency graph, but scheduling after S4.5 gives us a stable foundation and lets S6 benefit from durable session state (player reconnection across coordinator restarts becomes trivial).

**Research-driven design choices (from the master-plan research pass):**
- **pgx/v5 + pgxpool** — canonical Go Postgres driver, JSONB first-class support, batch API for efficient AsyncWriter flushes.
- **JSONB for player data, regular columns for keys** — username, last_seen, cell_id as indexed columns; everything game-specific (inventory, equipment, stats) in a single JSONB blob. Flexible schema evolution without migration pain.
- **`go:embed` migration files, no external tool** — keeps the migration runner self-contained. Migrations are `NNN_description.up.sql` files under `pkg/persist/migrations/`. Simple `schema_version` table tracks applied versions.
- **UPSERT via `INSERT ... ON CONFLICT`** — no separate get-then-update round-trip.
- **Connection string from env or Config field** — `postgres://localhost:5432/mmo?sslmode=disable` as the local-dev default.
- **Delete BoltDB entirely** — per the user's "no backward compat" preference. The store interface stays, the implementation gets swapped.

**Tech stack:** `github.com/jackc/pgx/v5`, `github.com/jackc/pgx/v5/pgxpool`, stdlib `embed`.

**Spec references:**
- [MMO Architecture: PostgreSQL for game DB](https://jahej.com/alt/2011_08_08_from-the-mmo-trenches-using-postgresql-for-the-game-database.html) (from the distributed-mesh design doc)
- [pgx v5 docs](https://pkg.go.dev/github.com/jackc/pgx/v5)

```go
package persist

import (
    "context"
    "embed"
    "fmt"
    "sort"
    "strings"

    "github.com/jackc/pgx/v5"
)

//go:embed migrations/*.up.sql
var migrationFS embed.FS

// RunMigrations applies all pending .up.sql files in order. Each
// migration is wrapped in a transaction and recorded in the
// schema_version table. Idempotent.
func RunMigrations(ctx context.Context, conn *pgx.Conn) error {
    // Read all migration files + sort by filename (NNN_name.up.sql).
    entries, err := migrationFS.ReadDir("migrations")
    if err != nil {
        return fmt.Errorf("read migrations: %w", err)
    }
    files := make([]string, 0, len(entries))
    for _, e := range entries {
        if strings.HasSuffix(e.Name(), ".up.sql") {
            files = append(files, e.Name())
        }
    }
    sort.Strings(files)

    // Apply each file.
    for _, fname := range files {
        body, err := migrationFS.ReadFile("migrations/" + fname)
        if err != nil {
            return fmt.Errorf("read %s: %w", fname, err)
        }
        if _, err := conn.Exec(ctx, string(body)); err != nil {
            return fmt.Errorf("apply %s: %w", fname, err)
        }
    }
    return nil
}
```

The first migration idempotently creates the tables and inserts version=1. Subsequent migrations would be numbered `002_...`, `003_...` etc. For S5 we only need `001_init`.

```go
package persist

import (
    "context"
    "encoding/json"
    "fmt"
    "time"

    "github.com/jackc/pgx/v5"
    "github.com/jackc/pgx/v5/pgxpool"
)

// PostgresStore implements Store via a pgx connection pool. Player
// state is stored in a JSONB data column alongside indexable
// metadata (cell_id, last_seen).
//
// The connection URL is typically supplied via Config.PostgresURL
// which defaults to the local dev instance under docker-compose.
type PostgresStore struct {
    pool *pgxpool.Pool
}

// NewPostgresStore opens a connection pool, pings the server, runs
// any pending schema migrations, and returns a ready-to-use store.
func NewPostgresStore(ctx context.Context, url string) (*PostgresStore, error) {
    cfg, err := pgxpool.ParseConfig(url)
    if err != nil {
        return nil, fmt.Errorf("parse postgres url: %w", err)
    }
    // Reasonable defaults for an MMO server: enough pool room for
    // concurrent cell flushes without hammering the DB.
    cfg.MaxConns = 16
    cfg.MinConns = 2
    cfg.MaxConnLifetime = 30 * time.Minute
    cfg.MaxConnIdleTime = 5 * time.Minute

    pool, err := pgxpool.NewWithConfig(ctx, cfg)
    if err != nil {
        return nil, fmt.Errorf("pgxpool new: %w", err)
    }

    if err := pool.Ping(ctx); err != nil {
        pool.Close()
        return nil, fmt.Errorf("postgres ping: %w", err)
    }

    // Run migrations on a dedicated conn.
    conn, err := pool.Acquire(ctx)
    if err != nil {
        pool.Close()
        return nil, fmt.Errorf("acquire for migration: %w", err)
    }
    err = RunMigrations(ctx, conn.Conn())
    conn.Release()
    if err != nil {
        pool.Close()
        return nil, fmt.Errorf("run migrations: %w", err)
    }

    return &PostgresStore{pool: pool}, nil
}

// LoadPlayer fetches a player by username. Returns (nil, false, nil)
// for a not-found (distinct from an actual error).
func (s *PostgresStore) LoadPlayer(username string) (*PlayerRecord, bool, error) {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()

    var data []byte
    var cellID string
    var lastSeen time.Time
    err := s.pool.QueryRow(ctx,
        `SELECT data, COALESCE(cell_id, ''), last_seen FROM players WHERE username = $1`,
        username,
    ).Scan(&data, &cellID, &lastSeen)
    if err == pgx.ErrNoRows {
        return nil, false, nil
    }
    if err != nil {
        return nil, false, fmt.Errorf("load player %q: %w", username, err)
    }

    rec := &PlayerRecord{
        Username: username,
        CellID:   cellID,
        LastSeen: lastSeen,
    }
    if err := json.Unmarshal(data, &rec.Data); err != nil {
        return nil, false, fmt.Errorf("unmarshal player %q: %w", username, err)
    }
    return rec, true, nil
}

// SavePlayer upserts a player record. Safe to call on both new and
// existing players.
func (s *PostgresStore) SavePlayer(rec *PlayerRecord) error {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()

    data, err := json.Marshal(rec.Data)
    if err != nil {
        return fmt.Errorf("marshal player %q: %w", rec.Username, err)
    }

    _, err = s.pool.Exec(ctx,
        `INSERT INTO players (username, data, cell_id, last_seen, updated_at)
         VALUES ($1, $2, $3, $4, NOW())
         ON CONFLICT (username) DO UPDATE
           SET data       = EXCLUDED.data,
               cell_id    = EXCLUDED.cell_id,
               last_seen  = EXCLUDED.last_seen,
               updated_at = NOW()`,
        rec.Username, data, rec.CellID, rec.LastSeen,
    )
    if err != nil {
        return fmt.Errorf("save player %q: %w", rec.Username, err)
    }
    return nil
}

// DeletePlayer removes a player record. No-op if the record doesn't exist.
func (s *PostgresStore) DeletePlayer(username string) error {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    _, err := s.pool.Exec(ctx, `DELETE FROM players WHERE username = $1`, username)
    if err != nil {
        return fmt.Errorf("delete player %q: %w", username, err)
    }
    return nil
}

// SaveBatch upserts multiple players in a single pgx.Batch. Used by
// AsyncWriter for efficient per-flush writes.
func (s *PostgresStore) SaveBatch(recs []*PlayerRecord) error {
    if len(recs) == 0 {
        return nil
    }
    ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()

    batch := &pgx.Batch{}
    for _, rec := range recs {
        data, err := json.Marshal(rec.Data)
        if err != nil {
            return fmt.Errorf("marshal player %q: %w", rec.Username, err)
        }
        batch.Queue(
            `INSERT INTO players (username, data, cell_id, last_seen, updated_at)
             VALUES ($1, $2, $3, $4, NOW())
             ON CONFLICT (username) DO UPDATE
               SET data       = EXCLUDED.data,
                   cell_id    = EXCLUDED.cell_id,
                   last_seen  = EXCLUDED.last_seen,
                   updated_at = NOW()`,
            rec.Username, data, rec.CellID, rec.LastSeen,
        )
    }

    br := s.pool.SendBatch(ctx, batch)
    defer br.Close()

    for i := 0; i < len(recs); i++ {
        if _, err := br.Exec(); err != nil {
            return fmt.Errorf("batch upsert %q: %w", recs[i].Username, err)
        }
    }
    return nil
}

// Close releases the connection pool.
func (s *PostgresStore) Close() error {
    s.pool.Close()
    return nil
}
```

# Phase S6: Gateway / client proxying

**Goal:** Playable multi-process gameplay. A browser client connects to the coordinator's WebSocket endpoint, authenticates, and gets seamlessly routed to the authoritative node via `MeshData.ClientInput`/`ClientFrame`. Handoff across nodes is transparent — the coordinator flips the upstream routing entry, the old node forwards any in-flight input to the new node via `ForwardInput`, and the client sees no disconnect.

**Why this is the last phase:** S1-S4 built the coordinator/node split; S4.5 made cross-node MeshData traffic work; S5 made state durable. S6 finally exposes the whole thing to clients. After S6 you can play `4node-basic` in a 3-process multi-host setup with handoffs visible on screen.

**Research-driven design choices (from the master-plan research pass):**
- **Gateway role stays inside the coordinator process for S6.** A separate gateway process (`--mode=gateway`) is deferred to a possible S6.5 — splitting it is mechanical once the proxy logic is stable, and keeping the coordinator as gateway for S6 means fewer moving parts.
- **`VirtualConnManager` on nodes** — a drop-in replacement for `net.ConnManager` that looks identical to the game-loop but routes Send/Recv through MeshData. Node-side game systems don't know they're running behind a proxy. Same pattern as the Unity "connection server" architecture common in MMO backends.
- **Per-session routing table** on the coordinator: `sessionID → {hostID, cellID}`. Populated after login via `Config.PlayerRouter`. Updated on `UpstreamSwitch` broadcasts from handoff. RLock-guarded for the hot-path lookup in the WebSocket recv loop.
- **`UpstreamSwitch` proto message** — already defined in S3 Task 2. Coordinator broadcasts it via the `MeshControl` stream when a player's authoritative host changes. Nodes that host the old cell start forwarding subsequent input via `MeshData.ForwardInput`; nodes that host the new cell start accepting.
- **Flip-then-forward semantics** — on handoff, coordinator flips its routing table first, then broadcasts `UpstreamSwitch`. Any input arriving at the old host during the single-tick overlap window gets forwarded via `ForwardInput`. Matches the S2 handoff design.
- **Login stays at the coordinator** — `Config.LoginHandler` runs in the coordinator process. After a successful login the coordinator picks a target cell via `Config.PlayerRouter`, records the routing, and sends a `PlayerAssignment` message (already defined in S3 proto) to the target node. The node creates the player session and starts receiving input via `ClientInput`.
- **Ping/pong at the gateway** — RTT is measured client-to-coordinator, which is the closest edge. Previously measured in game-loop via `ConnManager`; now the coordinator handles it independently of the node.
- **`--gateway-mode` flag on coordinator** controls behavior for in-process all-in-one testing:
  - `local-shortcut` (default): when the target host is the local Coordinator (i.e., all-in-one), skip the MeshData round-trip and call the existing ConnManager directly.
  - `always-proxy`: force the MeshData path even for local destinations, for testing the wire format.

**Research sources:**
- [MMO Architecture: clients, sockets, threads and connection-oriented servers](https://prdeving.wordpress.com/2023/10/13/mmo-architecture-client-connections-sockets-threads-and-connection-oriented-servers/) — validates the frontend proxy + stateless scaling approach
- [Cluster-Optimized MMO Server Protocol (Stanford)](https://www.scs.stanford.edu/17au-cs244b/labs/projects/kislyuk_zhai.pdf) — cross-shard routing patterns that informed the sessionID table design
- [SpatialOS upstream switch patent US10878146B2](https://patents.google.com/patent/US10878146B2) — the flip-then-forward pattern we already use in S2 handoff

**Tech stack:** No new dependencies. All work inside `pkg/universe/` + `pkg/net/` + existing proto messages.

### Task 3: `SessionRouter` on coordinator

- [ ] **Step 1: Define the type**

```go
// pkg/universe/session_router.go
package universe

type SessionRoute struct {
    SessionID uint32
    Username  string
    HostID    string
    CellID    string
}

type SessionRouter struct {
    mu     sync.RWMutex
    routes map[uint32]*SessionRoute // sessionID -> route
}

func NewSessionRouter() *SessionRouter {
    return &SessionRouter{routes: make(map[uint32]*SessionRoute)}
}

func (r *SessionRouter) Set(sessionID uint32, username, hostID, cellID string) {
    r.mu.Lock()
    r.routes[sessionID] = &SessionRoute{
        SessionID: sessionID,
        Username:  username,
        HostID:    hostID,
        CellID:    cellID,
    }
    r.mu.Unlock()
}

func (r *SessionRouter) Get(sessionID uint32) *SessionRoute {
    r.mu.RLock()
    defer r.mu.RUnlock()
    if route := r.routes[sessionID]; route != nil {
        cp := *route
        return &cp
    }
    return nil
}

func (r *SessionRouter) Update(sessionID uint32, hostID, cellID string) {
    r.mu.Lock()
    if route := r.routes[sessionID]; route != nil {
        route.HostID = hostID
        route.CellID = cellID
    }
    r.mu.Unlock()
}

func (r *SessionRouter) Remove(sessionID uint32) {
    r.mu.Lock()
    delete(r.routes, sessionID)
    r.mu.Unlock()
}
```

- [ ] **Step 2: Implement `BroadcastUpstreamSwitch` on meshControlServer**

Sends an `UpstreamSwitch` CoordMessage to every connected host. Every node updates its local routing view. The coordinator ALSO updates its own `SessionRouter` atomically so subsequent WebSocket inputs route to the new host.

```go
func (s *meshControlServer) BroadcastUpstreamSwitch(sessionID uint32, newHostID string) {
    // Update coordinator's routing table first.
    if s.coord.sessionRouter != nil {
        // Keep cellID if we have it (look up from HostRegistry by newHostID + current cell)
        // Simplest: just update hostID
        route := s.coord.sessionRouter.Get(sessionID)
        if route != nil {
            s.coord.sessionRouter.Update(sessionID, newHostID, route.CellID)
        }
    }

    msg := &meshpb.CoordMessage{
        CoordEpoch: s.coord.coordEpoch,
        Msg: &meshpb.CoordMessage_UpstreamSwitch{
            UpstreamSwitch: &meshpb.UpstreamSwitch{
                SessionId:  sessionID,
                NewHostId:  newHostID,
            },
        },
    }

    s.mu.RLock()
    hosts := make([]string, 0, len(s.streams))
    for hid := range s.streams {
        hosts = append(hosts, hid)
    }
    s.mu.RUnlock()

    for _, hid := range hosts {
        _ = s.sendCoordMessage(hid, msg)
    }
}
```

# Cross-phase risk notes

- **Don't let S4.5 leak into S6.** S4.5 is strictly about MeshData routing between cells. It should NOT touch ConnManager, VirtualConnManager, or anything related to client connections. Those are S6 concerns. If the scope creeps, stop and add the work to the S6 plan instead.

- **S5 Postgres deletion is irreversible.** Once `bolt_store.go` is gone, there's no way back to BoltDB without reverting commits. Make sure `just db-up` works reliably on the dev host before merging S5. If you need to test against multiple database states, use `just db-reset` aggressively.

- **S6 introduces session identity across processes.** The `connID` currently lives in the coordinator's ConnManager. When it's referenced on a node, that node needs to understand it's a virtual identity. VirtualConnManager maintains the mapping but nothing stops a node from creating a connID that collides with a coordinator-assigned one. For S6 we enforce: coordinator is the ONLY source of connID allocation; nodes never mint new ones. The node-mode Coordinator's ConnMgr is a `VirtualConnManager`, which never allocates — only looks up.

- **Stale session routes.** If a node crashes while holding player sessions, the coordinator's SessionRouter entries for those sessions become stale. The crash-reassignment path in S4's liveness watcher should also clear stale session routes. Add this to Task 7 of S6 (disconnect propagation) — when a host is marked Dead, iterate `sessionRouter.routes` and remove entries whose `HostID == dead.ID` (or mark them as needing reassignment).

- **`UpstreamSwitch` race with in-flight `ClientInput`.** Between the coordinator flipping its route and the broadcast arriving at the old host, there's a tiny window where the old host might receive input destined for the player that just moved. The S2 `ForwardInput` pattern already covers this for cross-cell handoff WITHIN a host; S6 extends it to cross-host via MeshData.ForwardInput. Make sure the forward path fires in the S6 integration test.

- **Integration tests under `-race`.** The pre-existing `TestSplitCell_*` races from way back in S3 are still there. Use `-run "S45|S5|S6|MeshFrame|HostNetwork|HostRegistry|TwoHost|Assign|S4"` to filter them out.

- **Context compaction between phases.** The user has already compacted context once during S3. Each phase should be fully committable before the next begins so the commit history is the primary source of truth. When the user compacts, the git log tells the complete story — this master plan is the scaffolding, not the memory.
